>> Variable 

Note : variable.tf file will contains default value , this file contain default value. 

Note : terraform.tfvars --> this file have more precendence over variable.tf , if any variable have value in this file , it will over write value of variable.tf. 

## To set enviroment variable in terraform ( windows )

setx TF_VAR_variablename value 

Note : in windows after setting enviroment variable, you need to reload the terminal. 

## To set enviroment variable in terraform ( linux and macos )

export TF_VAR_variablename = "value" 

echo TF_VAR_variablename    -- to check the enviroment variable

>> Data type in variable 

for eg : variable "image_id"{
type = string 
}

Note : The type argument in a variable allow  you to restrict the type value that will accepted the value for a variable. 

Note : If no type constraint is defined then a value of any type is accepted. 


## Data type is variable

1. string ---> sequence of unicode characters representing some text . for eg "hello"
2. list   ---> sequenctial list of value identifed by their position. starts with 0 . it is similar to array .
3. map    ---> a group of value identifed by name label. like { name="Neha" , age =25 }
4. number -- > for example 200.

>> Terraform provisioners 

Provisioners are used to execute the scripts on local or remote as a part of resource creation or destruction . 

# Terraform provisioners

local-exec  -- help to execute scripts on local server. used to run ansible playbook. 
remote-exec -- help to execute scripts on remote sever. 

Note : Above mentioned provisioners are not the only provisioners available, but these two are widely used. 

# Types of Terraform provisioners
1. creation time provisioners : It run only during creation, not during updating or any other lifecycle. 
                                If a creation time provisioner fails, the resource is maked as tainted 
2. destroy time provisioners : It's run before the resource is destroyed. 

## Terraform provisioner failure behaviour 

continue : ignore the error and continue with creation or destruction. 
fail : default behaviour, and it's mark the resource tainted.

>> Terraform workspace 

Terraform allows us to have multiple workspace, with each workspace we can have different set of enviroment variable associated with it . 

## workspace commands

1. terraform workspace -help -- to get help 
2. terraform workspace -- it show global options available in terraform workspace. 
3. terraform workspace list -- to list out all available workspace. 
4. terraform workspace create workspacename -- to create workspace. 
5. terraform workspace select workspacename -- to switch to particular workspace.

>> Terraform remote backend

Commiting tfstate files to git repo are not one of the best practice , in order to avoid pushing tfstate files to remote git repo we can store them at centralize location (remote backend ) which is not git or any version control system. 

There are many remote backend support by terraform, S3 is one of them. 

## Backend type 

1. standard backend type : state storage and locking 
2. Enhanced backend type : all features of standard  + remote management. 

Note : By terraform will store the file locally .

>> Terraform module calling form private git repo

reference : https://stackoverflow.com/questions/61100076/terraform-module-in-github-private-repo

1. Set up your ssh keys; make sure that your ~/.ssh/config file has a block like this:
Host USERNAME.github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_rsa 
	
	
2. Add this to your .tf file:

module "name_of_module" {
  source = "git@USERNAME.github.com:USERNAME/REPONAME.git//SUBDIR"
  ...
}
